러닝 플랫폼을 세 개의 경계로 나눈 이유

PAC-RUN은 리뷰 요약·레이스 플랜, 개인 러닝 분석, 크루 운영 콘솔을 한 앱에 몰아넣지 않고 스키마 소유권과 API 경계로 쪼갠 멀티서비스 백엔드입니다. 이 페이지는 제품 소개가 아니라, 설계 선택과 검증 근거를 정리한 엔지니어링 케이스 스터디입니다.

01 — Architecture

사용자 앱 둘, AI/데이터 코어 하나

공개 트래픽은 REVIEW/CREW가 받고, 비용·모델·교차 스키마 집약은 CORE가 담당합니다. “기능은 키우되 결합도는 더 엄격히” — 스키마 소유권으로 경계를 고정했습니다.

REVIEW Laravel CREW Laravel
↓ 내부 HTTP (동일 호스트) · 공개 경로 비공개
CORE FastAPI
public.users — 회원 정체성 공유

↓
PostgreSQL + pgvector S3 + CDN Claude · Apify
왜 모놀리스가 아닌가

AI 비용 가드·배치·Vision 파싱이 웹 요청 경로에 섞이면 장애 반경이 커집니다. CORE로 분리해 티어링·캐시·스케줄러를 한곳에서 통제합니다.

왜 네 번째 Admin 앱이 아닌가

관리 UX는 CREW/REVIEW 각 Filament 패널로 정렬하고, SSO·단일 admin 도메인은 후속 과제로 남겼습니다. 먼저 권한·비밀번호 재확인·이메일 인증을 맞췄습니다.

배포 단위

레포 3개 · 도메인 분기(Nginx) · GitHub → EC2. 서비스별 독립 배포로 롤백 범위를 제한합니다.

대회 리뷰 AI 요약

리뷰 한 건은 즉시 요약·감성분석하고, 대회 종합은 CRUD 때 dirty만 찍은 뒤 야간 배치가 재생성합니다. 본문이 없으면 빈 카드를 띄우지 않습니다.

레이스 플랜

코스 고저·구간, 날씨 스냅샷, 본인 러닝 로그를 넣어 개인 플랜을 만듭니다. 같은 입력이면 캐시를 재사용하고, 중량 모델은 이 경로에만 씁니다.

AI 러닝 분석

러닝 로그·PB·체성분(동의 후)을 컨텍스트로 단건 피드백, 주간 리포트, 훈련 스케줄을 만듭니다. 페이스는 VDOT로 계산하고, 같은 주·같은 로그는 캐시해 재호출하지 않습니다.

CREW 운영 페이지

Filament /admin에서 기수·지부·이벤트 점수·기록 검수·신청 폼을 운영합니다. 멤버 화면과 운영 콘솔을 같은 CREW에 두고, 역할·재확인으로 진입만 나눴습니다.

03 — Decisions

경계를 고정한 다섯 결정

기능 목록보다, 왜 그렇게 잘랐는지가 이 프로젝트의 핵심입니다.

01

서비스 경계 = 스키마 소유권

회원 정체성(public.users)만 공유하고, 활동 데이터는 소유 스키마 밖으로 raw JOIN하지 않습니다. CREW가 REVIEW 에디션을 직접 읽던 경로를 발견하면 CORE API로 되돌렸습니다.

Trade-off: 호출 hop 증가 → 장애 격리·권한·비용 가시성 확보
02

대회 마스터와 개최 인스턴스 분리

races는 카탈로그, race_editions는 연도별 개최로 리모델. 리뷰·날씨·플랜·공개 범위를 edition 기준으로 묶고, 무손실 백필 + 검증 커맨드로 이행했습니다.

검증: remodel 27/27 · E2E 12/12
03

GPX는 “업로드 시 1회 파싱”

좌표 단순화·km 마커·고도 세그먼트를 업로드 시점에 저장합니다. 레이스 플랜·지도 UI는 DB 컬럼만 읽어 사용자 수와 무관하게 코스당 비용을 고정합니다.

원칙: AI/파싱 비용은 요청 경로가 아니라 자산에 고정
04

AI 모델 티어링 + dirty 배치

이미지 파싱·개별 요약은 경량, 레이스 플랜·종합 분석은 중량 모델. 대회 종합은 리뷰 CRUD 때 dirty만 찍고 야간 배치가 재생성해 피크 비용을 평탄화합니다.

UX: dirty만 있고 본문 없을 때 빈 카드가 뜨지 않도록 가드
05

관리자 진입: 역할 + 재확인 + 이메일 인증

Filament 패널은 super_admin만, 비밀번호 재확인 세션(TTL), 이메일 미인증 차단. REVIEW는 손제작 대회관리를 별도 prefix로 병행해 이관 리스크를 줄였습니다.

보안 리뷰 피드백 → emailVerification을 패널에 명시적으로 연결

04 — Stack

운영에 올린 구성

AI & Integration
