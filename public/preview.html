Chapter 01

프로젝트 전체 구조

PAC-RUN은 러닝 커뮤니티를 위한 세 가지 독립 웹 서비스로 구성됩니다. 각 서비스는 분리된 도메인으로 운영되지만 하나의 Supabase PostgreSQL DB를 스키마(namespace)로 나누어 공유합니다.

조직 계층 구조

1차: 기수 (generation) → 1기, 2기, 3기... (필수) 2차: 지역 (region) → 반포, 연대, 인천, 군포 (필수) 3차: 조 (group) → A조, B조... 5~15명 (이벤트/점수용) 4차: 등급 (grade) → A/B/C (조 배정 시 자동 매칭) 5차: 훈련그룹 (training_group) → S/1~7조 (사용자 선택) 자동 매칭: A조 → grade:A → 120km 목표 / B조 → grade:B → 100km / C조 → grade:C → 80km

핵심 흐름 — 러닝 이미지 파싱 (2단계)

1
이미지 업로드 AJAX POST /running-logs/parse-image → CORE API로 전달
2
AI 파싱 CORE API → S3 업로드 → Claude Vision 파싱 → {거리/페이스/시간/run_date} JSON 리턴
3
Draft 저장 createDraft() → is_confirmed=false 행 INSERT (검수 대기 상태)
4
사용자 확정 파싱 결과 확인·수정 후 제출 → POST /running-logs/{id}/confirm
5
관리자 검수 Filament /admin → adminConfirm() → is_confirmed=true → 마일리지 자동 반영

CORE API 프로젝트 · api.pac-run.com

REVIEW와 CREW가 직접 하지 않는 AI 호출, 이미지 처리, 크롤링을 전담합니다. 같은 EC2 서버에서 내부 통신으로 연결되므로 외부 인터넷을 거치지 않아 빠르고 안전합니다.

언어 / 프레임워크

Python 3.14 / FastAPI

AI 엔진

Claude Vision (이미지 파싱)
Claude API (요약·분석)

API 문서

/docs Swagger UI
/redoc ReDoc

왜 별도 서버로 분리했나요? AI API 호출이나 크롤링은 느리고 비용이 발생합니다. 별도 서버로 분리하면 Laravel 쪽 코드가 단순해지고, 나중에 AI 모델을 교체할 때도 CORE만 수정하면 됩니다.

Chapter 05

DB 스키마 전체 구조

Supabase PostgreSQL을 사용하며 3개 스키마(namespace)로 테이블을 분리합니다. 세 서비스가 같은 DB를 쓰지만 테이블이 뒤섞이지 않습니다.

public 스키마 — 3개 서비스 공통

테이블주요 컬럼비고
users id, name, email, role, crew_id, branch_id, group_id, is_beta, invite_code, email_verified_at 통합 회원 (공유)
crews id, name, description 크루 정보
generations id, crew_id, name, recruit_start_at, recruit_end_at, is_recruiting, goal_km_grades JSONB, max_members 기수 정보 (CREW 신규)
regions id, name, crew_id 지역 (반포/연대/인천/군포)
branches id, name 지부

review 스키마 — REVIEW 전용

테이블주요 컬럼
races id, name, date, location, distances text[], entry_fee, ai_race_summary JSONB, created_at TIMESTAMPTZ(6)
reviews id, race_id, user_id, distance_km, rating, content, ai_summary, sentiment, image_urls JSONB, created_at
hashtags id, name (unique)
review_hashtags review_id, hashtag_id (pivot)
race_weather race_id, temperature, humidity, wind_speed, weather_condition

crew 스키마 — CREW 전용 (전체 18개+ 테이블)

테이블주요 컬럼 / 설명
running_logsuser_id, distance_km, duration_seconds, avg_pace_seconds, best_pace_seconds, is_indoor, calories, avg_heart_rate, elevation_m, image_url, parsed_data JSONB, is_confirmed
eventsname, type (main/sub/standalone), status, start_date, end_date, parent_event_id, score_type (mileage_grade/fixed/NULL), score_config JSONB, form_schema JSONB
event_scoresevent_id, user_id, group_id, score, source, awarded_by
user_goalsuser_id, goal_type (yearly/monthly), year, month, target_km, achieved_km, is_achieved
users_detailuser_id, generation_id, region_id, grade (A/B/C), training_group, badges JSONB, admin_memo
noticestitle, content, author_id, is_pinned, target_type (all/generation/region), target_ids JSONB
notice_readsnotice_id, user_id (UNIQUE 복합키)
bug_reportsuser_id, title, description, status, priority, attachment_url, admin_note, resolved_by
photo_galleriesuser_id, session_number, title, cover_image_url, album_url, photo_urls JSONB
application_formstitle, cohort, form_fields JSONB (동적 폼 빌더), open_from, open_until, is_active
applicationsform_id, name_enc, email_hash, email_enc, phone_enc, field_values JSONB, status, agree_privacy
google_formstitle, sheet_id, description, is_active, created_by

DB 작업 시 주의사항 모든 타임스탬프 컬럼은 TIMESTAMPTZ(6)으로 통일합니다. 배열 데이터는 JSONB로 저장합니다. public.users 등 기존 Supabase 테이블은 Schema::table로만 수정하고, DROP/CREATE는 절대 금지입니다.
Chapter 06

아키텍처 패턴 & 보안 규칙

Controller → Service → Model 3계층 아키텍처

REVIEW, CREW 두 Laravel 프로젝트 모두 동일한 3계층 구조를 따릅니다. 역할이 명확히 분리되어 유지보수와 재사용이 쉽습니다.

Controller (app/Http/Controllers/) 역할: 요청 수신 → $request->validate() → Service 호출 → 응답 반환 비즈니스 로직 작성 금지 │ (validate 후 Service 호출) ▼ Service (app/Services/) 역할: 비즈니스 로직 전담, 데이터 정제 예시: distances 파싱, 상태 자동 계산, CORE API 호출, S3 업로드 여러 Controller에서 재사용 가능하도록 작성 │ (정제된 데이터 전달) ▼ Model (app/Models/) 역할: DB insert / update / delete / select 단순 CRUD → Eloquent ORM 복잡한 JOIN / 집계 → DB::select() raw 쿼리 재사용 쿼리 → scope 또는 static 메서드로 정의

기능 추가 표준 절차

1
Model테이블 매핑, fillable, casts, scope 정의
2
Migration기존 테이블: Schema::table / 신규: Schema::create + hasColumn 멱등성 보장
3
Service비즈니스 로직 작성, Model 호출
4
Controllervalidate → Service 호출 → 응답
5
Routeweb.php 공개 라우트 / admin 그룹 등록
6
ViewBlade + Tailwind CSS (resources/views/ 하위)
7
브라우저 확인실제 동작 테스트 후 완료 보고

  • BugReportResource — 버그 제보 목록/응답
  • NoticeResource — 공지사항 CRUD
  • MeetingMinuteResource — 회의록 게시판
  • PhotoGalleryResource — 포토 갤러리
  • ApplicationFormResource — 기수 신청서 폼 빌더
  • ApplicationResource — 신청 기록 관리
  • GoogleFormResource — Google Forms 연동
  • GenerationResource — 기수 관리
  • BranchResource — 지부 관리
  • SmsResource — 단체 문자 발송 (솔라피 연동, 발신번호 드롭다운, 수신 상태 추적)
  • StatsOverview 위젯 — 수치 카드
  • 엑셀 다운로드/업로드 (maatwebsite/excel)

미완 리소스

  • 그룹 편성 UI (드래그앤드롭)
  • 게시판 관리 (자유/기수/지역/이벤트)
  • 관리자 로그
