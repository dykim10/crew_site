REVIEW v2 — 레이스 플랜 시스템 · 기획 완료 2026-06-15
"이 대회, 이 코스, 이 날씨에서 — 내 기록 기준으로 어떻게 달려야 최선이냐?" — Claude claude-opus-4-8 + pgvector RAG + GPX 직접 업로드

날씨 예측 3단계 전략

가까운 미래 (3일 이내) → 기상청 단기예보 API 정확도 높음 중간 거리 (1~2주) → 기상청 중기예보 API 먼 미래 (한 달 이상) → 5개년 평년 데이터 기반 AI 예측 레이스 시간대 오전 6시~오후 2시 최근 연도 가중치 높음 (이상기후 반영)

날씨 더블체크 전략

경로 1. 기상청 ASOS API → 공식 측정소 기온/습도 (시내 고정 위치) 경로 2. 사용자 이미지 파싱 → 코스 현장 실측 (호수·강변 등) → 데이터 축적 시 코스별 보정값 자동 생성 "춘천 코스: 기상청 -1.2°C / 습도 +8%"

날씨 해석 메시지 예시

⚠️ 습도 95% — 체감 온도보다 체력 소모가 큽니다. 평소 페이스보다 10~15초 여유를 두세요. 🌡️ 출발 13°C → 결승 예상 18°C 네거티브 스플릿보다 이븐 페이스를 권장합니다. 💨 남서풍 7km/h — 후반 코스 맞바람 구간 주의

RAG 아키텍처

▶ 데이터 축적 단계 사용자 A 춘천 / 13°C / 습도 95% / 3:56:17 사용자 B 춘천 / 13°C / 습도 92% / 4:12:33 ...수백 케이스 축적 ▶ RAG 검색 단계 새 사용자 → 춘천 마라톤 예상 14°C / 88% ↓ 비슷한 날씨 조건 pgvector 유사 검색 ↓ 실제 데이터 기반 페이스 전략 + 요약 생성 ▶ 캐싱 전략 (AI 비용 최소화) 기온 5°C 구간 · 습도 20% 구간 · 바람 3단계 → 동일 조건 구간 캐시 반환

AI 특장점 · 4대 핵심 인텔리전스
이미지 파싱 · SNS 리뷰 분석 · 날씨 교차 보간 — Claude API 티어링 (경량 / Opus)

01 · 러닝 이미지 AI 파싱  구현 완료

러닝 앱 스크린샷 한 장만 업로드하면 Claude Vision이 9개 수치를 즉시 추출합니다. 수동 입력 불필요, 연도 환각 보정으로 파싱 정확도를 높입니다.

파싱 항목 (9종) 거리 / 평균페이스 / 최고페이스 운동시간 / 칼로리 / 심박수 고도 / 실내외 / run_date → 연도 환각 보정 (sanitizeRunDate) → Draft 저장 → 사용자 확인 → 관리자 검수 → 다중 이미지 일괄 업로드 지원

02 · Instagram 유저 피드백 AI  구현 예정

PAC-RUN 공식 계정 및 크루 멤버 태그 포스트를 자동 수집해 감성분석을 수행합니다. 운영 인사이트를 관리자 대시보드에서 실시간 확인할 수 있습니다.

Instagram Graph API / Apify 1일 1회 자동 수집 ↓ crew.instagram_cache upsert 저장 ↓ Claude API 감성분석 positive / negative / neutral ↓ CREW 대시보드 그리드 노출 관리자 피드백 인사이트 집계

03 · SNS 대회 리뷰 AI 요약  일부 구현

플랫폼 내 리뷰는 이미 자동 분석됩니다. 향후 Instagram · YouTube · 네이버 블로그 공개 후기까지 통합해 대회별 종합 인텔리전스를 제공합니다.

현재 — 플랫폼 내 리뷰 AI 개별 요약 / 감성 / 키워드 (경량 모델) 종합 분석: dirty 큐 → 03:00 배치 (race_summarize) 예정 — SNS 크롤링 확장 Apify: Instagram · YouTube · 네이버 블로그 → race_sns_contents 수집 저장 → RAG pgvector 유사 케이스 검색 → 플랫폼 리뷰 + SNS 통합 종합 요약 생성

04 · 기상청 × 현장 날씨 보간  1단계 구현

기상청 ASOS 공식 측정소 데이터와 사용자 이미지에서 파싱된 코스 현장 실측치를 교차 분석합니다. 코스별 보정값을 누적해 시내 측정소와 실제 레이스 환경 간 오차를 자동으로 줄입니다.

경로 A — 기상청 ASOS 시내 고정 측정소 기온 13.2°C / 습도 79% / 풍속 2.1m/s 경로 B — 이미지 파싱 코스 현장 실측 기온 11.8°C / 습도 87% (강변·호수 기온 하강) → 코스 보정값 자동 누적 "춘천 의암호 코스: 측정소 대비 -1.4°C / 습도 +8%" → pgvector RAG → 날씨 조건별 페이스 전략 자동 추천

기상청 ASOS  구현 완료

전국 자동기상관측망(ASOS)의 시간 단위 데이터를 수집합니다. 대회 장소에 가장 가까운 측정소 기준으로 대회 당일 날씨를 단일 캐시로 저장하며, 재수집을 차단합니다.

수집 항목 기온 / 습도 / 풍향 / 풍속 / 강수량 weather_condition (KMA WC코드 → 한국어) 원본 raw_data JSONB 보존 저장: review.race_weather 단일 캐시 방어 레코드 존재 시 재수집 차단 (null 마커 포함) 서울(stn_id=108) 07:00 / 그 외 기본 08:00 예정: Google Geocoding → 최근접 ASOS 자동 매핑 5개년 평년 AI 예측 (중기 예보 보완)

Apify  구현 완료

클라우드 기반 웹 스크래핑 플랫폼으로 Instagram, YouTube, 네이버 블로그 공개 콘텐츠를 수집합니다. 공식 API 접근이 제한될 때 Fallback으로도 활용합니다.

사용 Actor Instagram Scraper → #서울마라톤 #대구마라톤 등 해시태그 YouTube Scraper → 대회명 + "후기/리뷰/완주" 저장 테이블 review.youtube_cache 유튜브 수집 (video_id UNIQUE) review.instagram_cache 인스타 수집 (post_id UNIQUE) crew.instagram_cache 크루 @pac-run 피드 (별개) 비용 모니터링 필수 월 $5 무료 크레딧 APScheduler 주 1회 (대회 시즌 전후 집중)

Instagram Graph API  연동 예정

Meta 공식 API로 @pac-run 비즈니스 계정의 포스트를 수집합니다. Long-lived Token 기반으로 APScheduler가 1일 1회 자동 수집하고 instagram_cache에 upsert합니다.

사전 조건 @pac-run 비즈니스/크리에이터 계정 전환 Meta Developer Console 앱 등록 Long-lived Token (60일, 수동 갱신 필요) CORE 비밀: [Parameter Store / 환경변수] 수집 항목 post_id / media_type / media_url caption / like_count / permalink / posted_at CORE API 엔드포인트 GET [비공개] 캐시 목록 반환 POST [비공개] 수동 수집 트리거 → CREW 대시보드 그리드 노출 → Apify를 Fallback으로 병행 운영

YouTube  구현 완료

마라톤·러닝 대회 후기 영상을 수집해 AI 종합 분석에 통합합니다. 영상 제목·설명·댓글을 텍스트로 추출하여 RAG 파이프라인의 데이터 소스로 활용합니다.

수집 방식 Apify YouTube Scraper 검색: 대회명 + "후기" / "리뷰" / "완주" 추출 항목 video_id / title / description view_count / published_at / url 저작권: 영상 자체 저장 금지 · URL+메타데이터만 저장: review.youtube_cache video_id UNIQUE · race_edition_id FK embedding vector(1536) (RAG용) AI 파이프라인 연결 → pgvector 임베딩 → RAG 유사 케이스 검색 → 레이스 플랜 생성 시 SNS 데이터 통합

AI 배포 자동화 · Claude Code Hook 기반
자연어 명령 한 줄 → Hook 자동 실행 → EC2 배포 완료 — 개발자 개입 최소화

배포 플로우

1
자연어 명령"커밋하고 배포해줘" — 한 줄 입력
2
Claude Codegit diff 분석 → 커밋 메시지 자동 작성 → commit + push
3
PostToolUse Hookgit push main 감지 → EC2 배포 스크립트 자동 실행
4
EC2 자동화git pull → composer install → npm build → migrate → restart
5
완료배포 결과 반환 — 전체 소요 약 60~90초

Hook 구성 (3레이어)

Hook 종류트리거역할
PreToolUsegit push main 직전배포 전 검증 알림
PostToolUsegit push main 완료EC2 배포 스크립트 자동 실행
PostToolUsegit commit 완료정의서 업데이트 알림
PostToolUseBash 명령 후패키지 취약점 자동 검사
Stop응답 종료 시배포 체크리스트 확인

Hook 설정 구조

// .claude/settings.json { "hooks": { "PostToolUse": [{ "matcher": "Bash", "hooks": [{ "type": "command", "command": "[배포 스크립트]", "timeout": 360, "statusMessage": "EC2 자동 배포 중..." }] }], "PreToolUse": [{ /* 배포 전 검증 */ }], "Stop": [{ /* 체크리스트 확인 */ }] } }

전통 방식 vs AI Hook 방식

항목전통 방식AI Hook 방식
커밋 메시지직접 작성AI 자동 생성
배포 트리거수동 SSH 접속Hook 자동 실행
배포 명령순서대로 수동 실행스크립트 자동화
사용자 입력10+ 단계자연어 1줄
핵심 차별점 Claude Code가 AI로서 액션을 트리거하고, Hook이 시스템 레벨에서 자동 실행합니다. 개발자는 자연어 한 줄만 입력하면 커밋 메시지 작성부터 EC2 서비스 재시작까지 자동 완료됩니다.
